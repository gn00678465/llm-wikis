### Scope notes

- Sections §6.5 (Skill Ownership) and §9 (Index Freshness) of the specification are **tombstones**: they document *removed* behavior. No row below requires anything they removed (skill overlay/install/patch, index discovery/parsing/freshness checking). Rows OFF-061 and OFF-112 instead assert the *absence* of that removed behavior, as regression checks.
- The `phase` column uses exactly `Phase 0`, `Phase 1`, `Phase 2`, `Phase 3` as defined in specification §19: Phase 0 = independent gates (this checklist + disposable capability spikes); Phase 1 = query core + offline tests; Phase 2 = hardening, live doctor/probe invalidation, plugin entrypoint validation, platform-native/process/installer tests, release workflow, live-provider rows; Phase 3 = independent verification, freeze, and publish-gate rows.

- `command_or_inspection` cites planned test file names from the implementation plan's Target File Map only as a concrete, independently re-runnable command once the crate exists; it is not itself a requirement and carries no normative weight — the specification cell (`requirement`) is authoritative.
